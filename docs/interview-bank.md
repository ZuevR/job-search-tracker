Вопросы, которые всплыли по ходу проекта, с краткими эталонными ответами.
Формат: **Вопрос** → ответ в 2–5 предложениях (как сказать на собеседовании) → ссылка на доку → где это в проекте.

## 1. Основы App Router

**Что значит `○ (Static)` в выводе `next build`? Что делает страницу динамической?**
Страница пререндерена один раз во время сборки, и готовый HTML (плюс RSC payload) отдаётся всем пользователям, обычно из CDN. Динамической её делают данные, которые есть только во время запроса: `cookies()`, `headers()`, `searchParams`, `connection()`, некэшированные `fetch` и запросы к БД. Клиентские компоненты и обработчики событий на статичность не влияют, потому что они тоже пререндерятся в HTML и затем гидрируются. С Cache Components (Next 16) динамику оборачивают в `<Suspense>`, и получается `◐ Partial Prerender`: статическая оболочка мгновенно отдаётся, а динамические части стримятся во время запроса. Легенда: `○` static, `◐` partial prerender, `ƒ` dynamic.
→ nextjs.org/docs/app/getting-started/caching · проект: задача 1.

**Чем `layout.tsx` отличается от `page.tsx`? Что происходит с layout при навигации?**
`page` — уникальный UI маршрута, именно он делает сегмент публичным URL. `layout` — общий UI, который оборачивает свой сегмент и все вложенные. При навигации внутри layout он не перемонтируется: состояние и DOM сохраняются, а перерисовывается только изменившаяся часть (partial rendering).
→ nextjs.org/docs/app/getting-started/layouts-and-pages

**Почему root layout обязан содержать `<html>` и `<body>`?**
В App Router нет отдельного `index.html` или `_document`, поэтому корневой layout сам является HTML-документом. `<head>` руками не пишется: Next собирает его из `metadata`/`generateMetadata` всех layouts и pages на пути маршрута.
→ nextjs.org/docs/app/api-reference/file-conventions/layout#root-layout

**Откуда берутся `PageProps` / `LayoutProps` без импорта?**
Это глобальные типы, которые `next dev`, `next build` и `next typegen` генерируют в `.next/types` по реальной структуре `app/`. Благодаря им `params` типизированы по сегментам маршрута, а `href` у `Link` проверяется на существующие маршруты.
→ nextjs.org/docs/app/api-reference/config/typescript

**Как задать `<title>` для каждой страницы? Что такое `title.template`, `default`, `absolute`?**
`metadata` из layouts и pages сливается по пути маршрута, и более глубокий сегмент перекрывает поля родителя. В layout задают `title: { template: '%s | App', default: 'App' }`. Страница отдаёт строку, и она подставляется в `%s`. `default` используется для дочерних сегментов, которые свой title не задали (например, 404). `absolute` игнорирует template родителя. Template действует на дочерние сегменты, а не на сегмент, где он объявлен.
→ nextjs.org/docs/app/api-reference/functions/generate-metadata#template · проект: задача 2.

## 2. Server vs Client Components

**Что можно передать пропсом из Server Component в Client Component?**
Только сериализуемое: props уходят в RSC payload по сети. Это примитивы, массивы, plain-объекты, `Date`, `Map`/`Set`, `Promise` (раскрывается через `use`) и JSX/`children`. Функции, экземпляры классов и символы передать нельзя. Исключение — Server Actions (`'use server'`): передаётся ссылка, а вызов превращается в запрос на сервер. Поэтому поведение передают данными (`exact: boolean`), а не колбэком (`isActive`).
→ nextjs.org/docs/app/getting-started/server-and-client-components · проект: задача 3.

**Рендерится ли Client Component на сервере? Что получает браузер?**
Да, при первой загрузке он тоже рендерится в HTML. Браузер получает три вещи: HTML (контент виден сразу), RSC payload (результат серверных компонентов, а на месте клиентских — ссылки на модули и их props) и JS-чанки клиентских компонентов для гидрации. Код Server Components в бандл не попадает. `'use client'` значит «этот модуль и его импорты попадут в бандл», а не «рендерится только в браузере».
→ nextjs.org/docs/app/getting-started/server-and-client-components · проект: задача 3.

**Как использовать стороннюю библиотеку с хуками в Server Component?**
Если библиотека ставит `'use client'` у себя (Base UI, Radix, shadcn-примитивы), её можно импортировать напрямую: граница проходит внутри пакета. Если не ставит, импорт из серверного компонента падает (хуки на сервере), и тогда нужен реэкспорт из своего файла с `'use client'`. Границу держат как можно ниже по дереву: клиентским делают лист (`NavLink`), а не весь `header`.
→ nextjs.org/docs/app/getting-started/server-and-client-components#using-third-party-components · проект: задача 3.

## 3. Загрузка данных, streaming, ошибки

**Что такое водопад запросов в RSC и как его убрать?**
Несколько `await` подряд выполняются последовательно, даже если запросы независимы: время = сумма задержек. Независимые запросы запускают одновременно — `Promise.all` или раздельные async-компоненты под своими `<Suspense>` (React рендерит соседей, не дожидаясь друг друга). Зависимый запрос (компании нужен `companyId` вакансии) остаётся последовательным, но цепочка целиком идёт параллельно с остальными. Минимум времени — критический путь, самая длинная цепочка зависимых запросов.
→ nextjs.org/docs/app/getting-started/fetching-data#parallel-data-fetching · проект: задача 4 (3052 → 1318 мс).

**Зачем `<Suspense>` для некэшированных данных в Next 16 и что значит `◐`?**
С Cache Components сборка пререндерит статическую оболочку маршрута. Некэшированный `fetch` вне `<Suspense>` ломает сборку: Next не знает, что отдать сразу. Варианты: `<Suspense>` (стриминг), `'use cache'` (кэш) или `instant = false` (честно блокирующий маршрут). С `<Suspense>` маршрут `◐`: оболочка и fallback-и готовы при сборке, блоки рендерятся на запрос и дописываются в тот же HTML-ответ. `<Suspense>` ловит ожидание только потомков, поэтому `await` переносят в компоненты блоков.
→ nextjs.org/docs/app/getting-started/caching · проект: задача 4.

**Почему вызов async-функции без `await` в компоненте опасен?**
Ошибка async-функции не бросается при вызове, а переводит её промис в rejected. Компонент не ждёт промис и рендерится успешно, React об ошибке не знает, Node пишет `unhandledRejection`. С `await` реджект становится `throw` в рендере и доходит до error boundary. Ловит линт: `@typescript-eslint/no-floating-promises`.
→ проект: задача 4.

**Чем `Promise.all` отличается от `Promise.allSettled` и чем опасен общий `catch` в RSC?**
`all` реджектится на первой ошибке (рендер страницы падает целиком), остальные запросы не отменяются. `allSettled` даёт статус каждого — частичная деградация. Но общий перехват гасит и служебные исключения Next (сигналы пререндера, `notFound()`, `redirect()`): их пробрасывают `unstable_rethrow`. Идиоматично — не ловить вручную, а ставить error boundary (`error.tsx`) на блок.
→ nextjs.org/docs/app/api-reference/functions/unstable_rethrow · проект: задача 4.

**Как безопасно собирать URL к внешнему API из пользовательских данных?**
Сегменты пути — через `encodeURIComponent`, query — через `URLSearchParams`. Иначе `?`, `&`, `/`, `#` меняют структуру запроса: пользователь подставляет свои параметры (`a?fail=1`) или выходит в другой путь (`../stats`). `fetch` не реджектит на 4xx/5xx — нужна проверка `res.ok`, а аннотация `Promise<T>` ничего не валидирует (для этого zod на границе).
→ проект: задача 4.

**Почему серверная переменная без `NEXT_PUBLIC_` и как ошибка env проявляется в проде?**
`NEXT_PUBLIC_` значение вшивается в клиентский бандл при сборке: его видит любой пользователь, а смена требует пересборки. Без префикса переменная доступна только на сервере и читается в рантайме. Проверка env до запроса роняет сборку при пререндере → Vercel не публикует сломанный деплой (fail-fast). В проде текст серверной ошибки скрыт от браузера (React #441), связь с логом сервера — по `digest`.
→ nextjs.org/docs/app/guides/environment-variables · проект: задача 4.

## 10. Качество и производительность

**Что делает `next/font`? Как он убирает layout shift?**
Google-шрифт скачивается при сборке и раздаётся как статический ассет с нашего домена: браузер не ходит в Google, нет лишнего соединения, и это лучше для приватности. Для CLS Next генерирует fallback-шрифт (например, `"Geist Fallback"` на основе Arial) с `size-adjust` и overrides метрик, чтобы при подмене fallback → web-шрифт текст не прыгал. Подключают через `className` или `variable`. `variable` только объявляет CSS-переменную, а применяет её ваш CSS (в Tailwind 4 — через `--font-sans` в `@theme`). `subsets` определяет, какие наборы глифов грузить: без `cyrillic` русский текст уйдёт в системный шрифт.
→ nextjs.org/docs/app/api-reference/components/font · проект: задача 2.

**Почему класс Tailwind не применяется, хотя он есть на элементе?**
В Tailwind 4 утилиты лежат в нативном CSS-слое `@layer utilities`. Любой стиль **вне** слоёв побеждает любой стиль внутри слоя, независимо от специфичности. Поэтому `body { background: … }` в `globals.css` перебивает `bg-gray-50` на `<body>`. Решение — класть свои базовые стили в `@layer base`. Для `!important` порядок слоёв обратный.
→ developer.mozilla.org/en-US/docs/Web/CSS/@layer · tailwindcss.com/docs/adding-custom-styles · проект: задача 2.
