## Условие

**Зачем:** граница Server/Client — вопрос №1 по App Router на собеседованиях: что попадает в бандл, где выполняется код, что можно передать через props. Сейчас `SiteHeader` и `DashboardNav` целиком клиентские, хотя интерактивна в них одна строчка. shadcn/ui — фактический стандарт UI-кита для Next, и на нём удобно увидеть, какие компоненты клиентские и почему.

**Прочитать:**
- https://nextjs.org/docs/app/getting-started/server-and-client-components — целиком, особенно «How do Server and Client Components work», «Reducing JS bundle size», «Passing data from Server to Client Components», «Interleaving Server and Client Components».
- https://react.dev/reference/rsc/use-client — разделы «How 'use client' marks client code» и «Serializable types returned by Server Components».
- https://ui.shadcn.com/docs/installation/next — установка.

**Сделать:**
1. Подключи shadcn/ui (`yarn dlx shadcn@latest init`) и добавь компоненты `button`, `card`, `input`, `dropdown-menu`. Посмотри, что появилось в проекте (`components.json`, `components/ui/`, `lib/utils.ts`, изменения в `globals.css`).
2. **Сузь клиентскую границу.** `SiteHeader` и `DashboardNav` должны стать серверными. В клиентский компонент выносится только то, что действительно требует клиента. В итоге `'use client'` стоит только там, где без него нельзя.
3. Переведи шапку, сайдбар и «Быстрый поиск» на компоненты shadcn. Как отрендерить `next/link` в виде кнопки — смотри в сгенерированном `components/ui/button.tsx` и в доке своей версии.
4. В шапку добавь меню пользователя на `DropdownMenu`: заглушка с пунктами «Профиль» и «Выйти» без логики.
5. Лендинг: короткий hero (заголовок, подзаголовок, кнопка «Перейти в кабинет») и три карточки `Card` с фичами. Стили не вылизывай, максимум 20 минут.
6. **Эксперимент «где выполняется код».** Создай два временных компонента: серверный `<ServerProbe />` и клиентский `<ClientProbe />` (с `'use client'`). В каждом сделай `console.log('<имя>', typeof window)`. Положи оба на `/dashboard`. Затем:
   - а) полная перезагрузка `/dashboard`: где появился каждый лог — терминал `yarn dev` или консоль браузера, и с какой пометкой?
   - б) уйди на `/dashboard/vacancies` по ссылке, перезагрузи страницу там и вернись на `/dashboard` по ссылке: что изменилось?
   - в) импортируй `ServerProbe` **внутрь файла** `ClientProbe` и отрендери его там: где теперь его лог?
   - г) передай `<ServerProbe />` в `ClientProbe` через `children` из серверной страницы: где лог?

   Результаты запиши таблицей в раздел «Результат», объясни строку в) и г) и удали пробы.

## Вопросы на понимание

**Почему `NavLink` получает флаг `exact`, а не функцию `isActive` от родителя?**
Ответ Ромы: функция не сериализуема, её нельзя передать пропсом из серверного компонента в клиентский.
Дополнение: props на границе Server → Client сериализуются в RSC payload и уходят по сети. Можно передавать примитивы, массивы, plain-объекты, `Date`, `Map`, `Promise` и JSX. Функции нельзя, исключение — Server Actions (передаётся ссылка, вызов идёт запросом на сервер).

**Зачем `nav-link.tsx` нужен клиент?**
Ответ Ромы: `usePathname` для подсветки активной ссылки.
Дополнение: layout не перерендеривается при клиентской навигации и не получает путь в props, поэтому сервер не может поддерживать подсветку актуальной.

**`layout.tsx` серверный, а внутри него клиентский `Input`. Что будет в HTML, а что догрузится JS-ом?**
Ответ Ромы: `Input` рендерится на сервере, JS догружает то, что нужно, чтобы его оживить. ✅
Дополнение: в RSC payload вместо `Input` — ссылка на клиентский модуль и props. Код самого layout в бандл не попадает. Нативный `<input>` работает ещё до гидрации, а поведение Base UI появляется после неё.

**Почему `'use client'` ставят у примитива в библиотеке?**
Ответ Ромы: иначе пришлось бы самому оборачивать каждый примитив. 🟡 (следствие, а не причина)
Дополнение: без директивы модуль считается серверным, и хуки внутри него ломают сборку при импорте из серверного компонента. Обход для старых библиотек — реэкспорт из своего файла с `'use client'`. Директива у примитива держит границу узкой: `Card` без хуков остаётся серверным.

**В `dropdown-menu.tsx` есть `"use client"`, а в `button.tsx` нет, хотя оба на клиентских примитивах Base UI. Что меняет директива?**
Ответ Ромы: не знал. ❌
Разбор: обёртки в `dropdown-menu.tsx` не используют хуков и только пробрасывают props в `@base-ui/react/menu`, где `'use client'` уже стоит. Без директивы ничего бы не сломалось: обёртки стали бы серверными, а граница сдвинулась бы внутрь Base UI. С директивой клиентским становится весь модуль, и обёртки попадают в бандл (разница копеечная). Ограничения на props (без функций из сервера) одинаковы в обоих случаях. shadcn ставит директиву на всякий случай и как пометку «интерактивный компонент». Вывод: `'use client'` помечает границу модуля в графе импортов, а не «интерактивность».
