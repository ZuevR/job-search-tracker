## Условие

**Зачем:** граница Server/Client — вопрос №1 по App Router на собеседованиях: что попадает в бандл, где выполняется код, что можно передать через props. Сейчас `SiteHeader` и `DashboardNav` целиком клиентские, хотя интерактивна в них одна строчка. shadcn/ui — фактический стандарт UI-кита для Next, и на нём удобно увидеть, какие компоненты клиентские и почему.

**Прочитать:**
- https://nextjs.org/docs/app/getting-started/server-and-client-components — целиком, особенно «How do Server and Client Components work», «Reducing JS bundle size», «Passing data from Server to Client Components», «Interleaving Server and Client Components».
- https://react.dev/reference/rsc/use-client — разделы «How 'use client' marks client code» и «Serializable types returned by Server Components».
- https://ui.shadcn.com/docs/installation/next — установка.

## Результат

### Клиентские файлы (кроме `components/ui/`)

- `components/nav-link.tsx` — `usePathname` для подсветки активной ссылки. Layout не перерендеривается при навигации и не получает путь в props, поэтому на сервере это не сделать.

### Эксперимент «где выполняется код» (пункт 6)

| Шаг | Лог | Терминал (`yarn dev`) | Консоль браузера | `typeof window` |
|---|---|---|---|---|
| а) полная перезагрузка `/dashboard` | ServerProbe | ✅ 1 раз | ✅ с бейджем `Prerender` (серый) | `undefined` в обоих местах |
| а) полная перезагрузка `/dashboard` | ClientProbe | ✅ 1 раз | ✅ 2 раза: обычный и приглушённый (`installHook.js`) | терминал `undefined`, браузер `object` |
| б) переход по ссылке на «Обзор» | ServerProbe | ✅ 1 раз | ✅ с бейджем `Prerender` | `undefined` в обоих местах |
| б) переход по ссылке на «Обзор» | ClientProbe | ❌ нет | ✅ 2 раза (Strict Mode) | `object` |
| в) `ServerProbe` импортирован внутри `ClientProbe` | ServerProbe | ✅ 1 раз | ✅ 2 раза, **без** бейджа `Prerender` (Strict Mode) | терминал `undefined`, браузер `object` |
| г) `<ServerProbe />` передан в `ClientProbe` через `children` | ServerProbe | ✅ 1 раз | ✅ только replay с бейджем `Prerender` | `undefined` в обоих местах |
| г) `<ServerProbe />` передан в `ClientProbe` через `children` | ClientProbe | ✅ 1 раз | ✅ 2 раза (Strict Mode) | терминал `undefined`, браузер `object` |

Пояснения к а):
- `Prerender` в браузере — console replay: Next в dev пересылает логи серверных компонентов в консоль и помечает их окружением, где код выполнился. В браузере код не выполнялся, поэтому `typeof window` = `undefined`.
- Второй приглушённый `ClientProbe` — Strict Mode в dev рендерит компонент дважды, а React DevTools (`installHook.js`) глушит повторный лог. В проде лог будет один.
- `ClientProbe` в терминале. Ответ Ромы: клиентский компонент тоже рендерится на сервере для HTML; `'use client'` значит, что компонент попадёт в бандл и гидрируется в браузере. ✅ Server Components выполняются только на сервере, Client Components — и на сервере (SSR), и в браузере (гидрация и все последующие рендеры).
- б) `ClientProbe` не выполнился на сервере. Ответ Ромы: при навигации сервер отдаёт только RSC payload, HTML не нужен. ✅ Чтобы собрать payload, сервер выполняет серверные компоненты меняющегося сегмента (`page`), а общий layout не перезапрашивается (partial rendering). Клиентские компоненты рендерит браузер, их JS уже загружен. В проде статический `/dashboard` (`○`) собирается на `build`, а `Link` делает prefetch, поэтому при переходе `ServerProbe` не выполнится вовсе. В dev всё рендерится по запросу.
- в) Ответ Ромы: модуль импортирован из клиентского файла, поэтому стал клиентским. ✅ Граница проходит по графу импортов, а не по дереву JSX: всё, что импортирует файл с `'use client'`, становится клиентским, даже без собственной директивы.
- г) Ответ Ромы: передача через `children` работает иначе, компонент остаётся серверным. 🟡 (факт без механизма)
  Механизм: `ServerProbe` импортирует и рендерит серверная `page.tsx`. `ClientProbe` получает в `children` уже готовый результат рендера (кусок RSC payload), а не код компонента, и работает как слот. Важно не где компонент стоит в JSX, а кто его импортирует и рендерит. Это interleaving.
- Практика: клиентская модалка с `useState` и серверный список из БД внутри. Ответ Ромы: серверный компонент передаётся через `children`; если импортировать «в лоб», серверный станет клиентским и не сможет ходить в базу. ✅
  Что ломается конкретно: `async`-компонент нельзя рендерить как клиентский; драйвер БД (`pg`, `fs`) не собирается для браузера; в худшем случае ничего не падает, но логика утекает в бандл, а env без `NEXT_PUBLIC_` становятся `undefined`. Защита: `import 'server-only'` в data access layer (задача 8).

## Вопросы на понимание

**Почему `NavLink` получает флаг `exact`, а не функцию `isActive` от родителя?**
Ответ Ромы: функция не сериализуема, её нельзя передать пропсом из серверного компонента в клиентский.
Дополнение: props на границе Server → Client сериализуются в RSC payload и уходят по сети. Можно передавать примитивы, массивы, plain-объекты, `Date`, `Map`, `Promise` и JSX. Функции нельзя, исключение — Server Actions (передаётся ссылка, вызов идёт запросом на сервер).

**Зачем `nav-link.tsx` нужен клиент?**
Ответ Ромы: `usePathname` для подсветки активной ссылки.
Дополнение: layout не перерендеривается при клиентской навигации и не получает путь в props, поэтому сервер не может поддерживать подсветку актуальной.

**`layout.tsx` серверный, а внутри него клиентский `Input`. Что будет в HTML, а что догрузится JS-ом?**
Ответ Ромы: `Input` рендерится на сервере, JS догружает то, что нужно, чтобы его оживить. ✅
Дополнение: в RSC payload вместо `Input` — ссылка на клиентский модуль и props. Код самого layout в бандл не попадает. Нативный `<input>` работает ещё до гидрации, а поведение Base UI появляется после неё.

**Почему `'use client'` ставят у примитива в библиотеке?**
Ответ Ромы: иначе пришлось бы самому оборачивать каждый примитив. 🟡 (следствие, а не причина)
Дополнение: без директивы модуль считается серверным, и хуки внутри него ломают сборку при импорте из серверного компонента. Обход для старых библиотек — реэкспорт из своего файла с `'use client'`. Директива у примитива держит границу узкой: `Card` без хуков остаётся серверным.

**В `dropdown-menu.tsx` есть `"use client"`, а в `button.tsx` нет, хотя оба на клиентских примитивах Base UI. Что меняет директива?**
Ответ Ромы: не знал. ❌
Разбор: обёртки в `dropdown-menu.tsx` не используют хуков и только пробрасывают props в `@base-ui/react/menu`, где `'use client'` уже стоит. Без директивы ничего бы не сломалось: обёртки стали бы серверными, а граница сдвинулась бы внутрь Base UI. С директивой клиентским становится весь модуль, и обёртки попадают в бандл (разница копеечная). Ограничения на props (без функций из сервера) одинаковы в обоих случаях. shadcn ставит директиву на всякий случай и как пометку «интерактивный компонент». Вывод: `'use client'` помечает границу модуля в графе импортов, а не «интерактивность».

**Зачем React нужен `key` в списке? Почему индекс — плохой ключ и когда он допустим?**
Ответ Ромы: для оптимизаций и сокращения числа ре-рендеров. Индекс плох, потому что позиции меняются, и React считает элементы теми же, хотя данные уже другие. Индекс допустим, если добавляем только в конец. 🟡
Дополнение: `key` задаёт идентичность элемента при reconciliation (обновить, переместить, создать или удалить), а не уменьшает число ре-рендеров (это задача `memo`). При ключе-индексе к позиции привязываются состояние, значение неуправляемого `input`, фокус и DOM-узел. После вставки в начало они «уезжают» к чужим данным. Индекс допустим, только если список статичен или растёт строго в конец (без удаления, сортировки и фильтрации) и у элементов нет своего состояния. Бонус: `key={id}` — способ намеренно сбросить состояние компонента.
